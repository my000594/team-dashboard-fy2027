# data/ データフォーマット詳細（ClaudeCode用）

このファイルはプロジェクトルートの`CLAUDE.md`から2026-08-31に分離した。`data/`配下のファイルを読み書きするときだけClaude Codeが自動で読み込む仕組み（ネストされたCLAUDE.mdの遅延読み込み）を利用し、ページのUI実装など`data/`に触れない作業ではロードされないようにするための分割。プロジェクト全体の概要・ページ別詳細・技術スタック等はルートの`CLAUDE.md`を参照。

各CSVを変更・追加した場合は、ルートCLAUDE.mdの更新ルール表（ファイル構成・データフォーマット関連）と合わせてこのファイルも更新すること。

### data/info.csv（Notionエクスポート）
```
タイトル,本文,開始日,終了日,種別,表示期間,表示順
社内規定検定,説明文,2026/08/01,2026/09/30,deadline,期間,1
3SEレポート提出リマインド,説明文,2026/08/01,,info,恒常,2
```
- 種別セレクト：`deadline`（赤）/ `event`（青）/ `info`（緑）
- **表示期間セレクト（2026-08-27追加）**：`期間`（デフォルト）/ `恒常`。「期間」は従来通り開始日〜終了日の範囲内のものだけ表示。「恒常」は終了日を必須にせず、期限での絞り込みを一切行わない代わりに📌ミニリストとして常時表示する（詳細な表示ロジックはindex.html・info.htmlの各セクション参照）。**恒常項目を終わらせたい（引退させたい）場合の自動失効の仕組みは無いため、Notion側で「表示期間」を「期間」に変えて終了日を入れる、という手動操作が運用として必要**（「表示期間」プロパティが空欄の行は既存データとの後方互換のため「期間」として扱う）
- 今日が開始日〜終了日の範囲内の「期間」項目だけ表示。index.htmlは最大5件、info.htmlは全件＋期限切れのアーカイブ表示（恒常項目はこのアーカイブ判定の対象外）
- 表示順（Number）：値が入っているものを昇順で先に表示し、未設定のものは終了日昇順（恒常項目は開始日昇順）でその後に続く。sync-notion.mjsで事前ソートした上でCSVに出力し、index.html・info.htmlでもクライアント側で同じロジックを適用（恒常・期間はそれぞれ別グループとして独立にソート）
- **Notion側で「表示期間」（セレクト、選択肢：恒常／期間）プロパティを追加しないと`scripts/sync-notion.mjs`の`assertProperties`がエラーになりinfo.csvが同期されなくなる点に注意**（他のDBの同期は影響を受けない）。既存項目は「期間」を設定しておけば現状の挙動のまま変わらない

### data/sales.csv（Notionエクスポート・縦持ち）
```
タイトル,顧客名,月,予算,実績,予算差（見込）,予算差（実績）
2026年8月,CTC,2026年8月1日,3000,3240,,240
```
- 月はNotion同期時に「2026年8月1日」のような日本語表記の日付文字列になる（`new Date()`では`Invalid Date`になるため、月をパースする箇所は必ずsales.html/index.html内の自前`parseMonth()`を使うこと。手動バッチ運用時のExcelエクスポートでは「2026/08/01」形式になることもあるため、`parseMonth()`は両方の表記に対応している）
- 予算・実績は数値型、単位：千円
- 実績=0は未確定月
- 予算差（見込）・予算差（実績）：Notion側で計算済みの数式列（顧客×月ごとに1つ）。月が確定するまでは見込、確定後は実績の差分を使う運用。値が無い行は空欄のままでよい（sales.htmlはnullとして扱い「—」表示にする）

### data/certifications.csv（Notionエクスポート・縦持ち）
```
資格名,氏名,資格区分,資格分野,資格取得日,有効期限,デジタルバッジ,備考
基本情報技術者,山田 太郎,国家資格,IT,2011-11-17,,,
```

- 資格名：Notion側のタイトル型プロパティ（2026-07-28にselectから変更）。資格名を固定の選択肢に縛らず自由記述できるようにするための変更。sync-notion.mjsは`getTitle(props['資格名'])`から取得している
- 氏名・資格区分（国家資格／認定資格）・資格分野（現状「IT」のみ）はいずれも自由記述可（Notionのセレクト値をそのまま採用）。Notion側で選択肢を増やしてもコード側の追随は不要

- 有効期限：更新が必要な資格（AWS・Azure・GCP認定など）のみ設定。基本情報技術者・応用情報技術者・情報処理安全確保支援士のような無期限資格は空欄のままにする

- 備考：自由記述の補足欄
- skill.htmlのマトリクスタブ内に「💯 保有資格」カードとして、資格名×メンバーのマトリクスで表示される。有効期限のあるものは今日の日付基準で「期限切れ」（赤）／「更新目安＝期限まで90日以内」（amber）／それ以外（緑）に自動判定。取得日は年月表記でセル下に表示し、デジタルバッジがあれば🏅リンクを表示
- 保有資格カードには「全体／区分別／分野別」の表示切り替えタブがある。区分別・分野別はNotionの「資格区分」「資格分野」の値ごとにグループ分けして表示する。区分・分野の選択肢が増えてもコード修正不要（実データから動的にグルーピング）。**グループごとに別々の`<table>`は組まず、1つの`<table>`の中にグループ区切り行（`tr.group-row`。colspanでメンバー列をまたぐ）を挟む実装**にしている（`certTableHeadHTML`/`certTableRowsHTML`/`renderCertMatrix`）。以前はmember.htmlのライン別表示と同じ`.group-section`/`.group-header`＋グループごとに別tableだったが、tableを分けるとブラウザが列幅をtableごとに独立計算するため、資格名が短いグループで名前列が狭くなり、グループ間で列がずれて見える不具合があった
- Notion側データベース名：「💯 保有資格」（「2027年7月期」ページ配下、他のDBと同階層）。データソースID: `f5afd475-cc86-410f-8642-848c7fc4122c`
- 行の並び順はNotion側の「表示順」（Number）プロパティ昇順。CSVには出力されずNotion同期時のソートにのみ使う。1行＝1人×1資格のため、同じ資格を複数人が保有する場合は**資格名ごとの表示順の最小値**で比較する（sync-notion.mjsの`certOrderByName`）。これにより、表示順を全員分そろえて入力していなくても（例：資格を最初に取得した1人の行にだけ入力）、資格・資格分野単位の並びがブレない。表示順が同一資格の全行にきちんと揃っていれば当然その値通りに並ぶので、資格分野ごとにまとまるよう番号を採番（例：IT系=1〜10、技術・技能資格系=11〜20）すれば、資格分野別タブのグルーピング順も自動的にその通りになる（分野の固定順をコード側にハードコードする必要はない）
- このデータベースは手動バッチ運用の対象外（Notion API自動同期のみ対応、update_*.batなし）

### data/org_chart.csv（Notion「組織構成」ページ本文から自動抽出）
```
表示名,リンク
2026年8月,https://syshd01-my.sharepoint.com/...
```
- Notion側の出典：DBではなく「👥 組織構成」ページ本文に貼られたファイル添付ブロック（外部ドライブ・SharePoint等へのリンク）。見出しやトグルの文言でセクションを判定せず、**ページ配下をブロックツリーごと再帰的に走査してfile型ブロックを全部拾う**方式（sync-notion.mjsの`collectFiles`）。理由：見出し／トグルの文言をキーにマッチさせる方式だと、Notion側で見出し名を書き換えるたびに検出が壊れていたため。このページには組織構成図ファイル以外を置かない運用が前提。メンバーDBが埋め込まれた「全体」トグルはchild_databaseとして現れ、file型ではないため自然にスキップされる。ページ内の掲載順（＝Notion上で追加した順）のままCSVに出力される
- 表示名：Notion側でそのファイルに設定した**ファイル名（ファイルブロックをクリックして直接リネームする欄）**を最優先し、無ければ**キャプション**（ファイル下に「Add caption」で付ける小さい文字）を使う。どちらも未設定の場合は「組織構成図」とフォールバック表示
- 運用：月1回、その時点の組織構成図ファイルをNotionの「組織構成」ページ本文に追加し、ファイル名を対象年月（例：`2026年8月`）にリネームする。最大でも年12件（2026/8〜2027/7）の想定のため、ダッシュボード側は履歴アーカイブを持たず全件をmember.html（メンバー一覧の下、ALLタブのみ）にチップ表示するだけ
- このデータは手動バッチ運用の対象外（Notion API自動同期のみ対応、update_*.batなし）
