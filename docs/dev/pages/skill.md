# skill.html（スキルマップ）

> ルート`CLAUDE.md`から分離した開発メモ（2026-11-08）。該当ファイルを変更する前に読み、構造に関わる変更をしたらここを更新すること。
> 文中の「〇〇.htmlセクション」は`docs/dev/pages/〇〇.md`、「△△.js節」は`docs/dev/shared/`、「データフォーマット節」は`data/CLAUDE.md`、「組織設定」節・「技術スタック」節はルート`CLAUDE.md`を指す。

- `data/skill.csv`（氏名×スキル名の縦持ち）・`data/members/member_master.csv`・`data/certifications.csv`を並行fetchしてPapaParseで解析
- タブ3種：マトリクス（メンバー×スキルの一覧、レベルをドットで表示）／レーダーチャート（メンバーを選んでスキルレーダー表示）／スキル検索（スキル名で検索し保有者をレベル順表示）
- 上記3タブとは別に「評価時期」タブ（2026年8月／11月・2027年2月／5月）があり、3タブすべてに共通で適用される。選択中の時期はメンバー選択・タブ切り替えをまたいで保持される。デフォルトは「評価データが1件以上入っている時期のうち最新のもの」（全期未入力ならPERIODSの先頭）。単純にPERIODS配列の末尾を既定にすると、まだ評価未実施の期が既定表示になり一見データが反映されていないように見えるための対応。新しい時期が追加されたら`config/org.json`の`skillPeriods`（一次情報源）・scripts/sync-notion.mjsの`SKILL_PERIODS`定数・you-widget.jsの`YOU_SKILL_PERIODS`定数の3箇所を揃えて追記し、このセクションも更新すること（詳細は「組織設定（config/org.json）」節を参照）
- メンバーの並び順は`member_master.csv`のステータス「在籍」の行順（＝メンバー一覧の表示順）に固定。skill.csv側の出現順やデータ入力状況が変わっても並びは変化しない。**member_master.csvに一切見当たらない氏名（表記ゆれ等）のみ**末尾に出現順で追加する（2026-08-12修正：以前はステータスが在籍以外＝異動・退職者もこの「見当たらない氏名」判定に引っかかり、skill.csv側に行が残っている限り末尾に紛れ込み続けるバグがあった。現在はmember_master.csv側の全氏名（ステータス不問）を除外リストとして持ち、在籍以外の人はskill.csvに行が残っていても復活しない）。スキル一覧（行）はskill.csv内の出現順をそのまま採用
- 評価レベル（1〜5）の基準はページ内に静的なテキストで表示（Lv.1:知っている／Lv.2:触ったことがある／Lv.3:業務で使える／Lv.4:得意／Lv.5:エキスパート）。基準文言はCSVではなくskill.html内にハードコーディングしているため、基準を変更する場合はskill.html本体を編集すること。以前あった「資格はLv.5＝取得済み」の注記は、2026-07-28のNotion DB再構成で資格系スキルが廃止されたため削除済み
- マトリクスのドット色は「カテゴリ」列の値から動的に割り当て（knowledge.htmlのカテゴリ色付けと同じ方式）。Notion側でカテゴリの選択肢が増えてもコード修正不要
- **「その他（自由記入）」の並び替え・非表示**（2026-08-18追加）：ヒアリングシートの「その他（自由記入）」は、本人がNotion上でスキル名自体を`その他（Perl）`のように書き換えて使う設計。書き換えると、`skillList`を初出順（＝全員分の行を氏名→表示順で流し見た順）で構築するだけの従来ロジックでは元の「その他（自由記入）」から離れた位置（多くの場合55種の一番最後）に来てしまう不具合があった（谷野亘が6件・部長（参考値）が1件書き換えたことで発覚）。init()内でskillList構築直後に並び替えを行い、`その他（自由記入）`以外で`その他（〇〇）`の形をした名前は、同じサブカテゴリの`その他（自由記入）`の直後にまとめる（対象者・件数は問わない。今後も他の部下が書き換えれば同じ位置に増えていく）。書き換えられた行に矢印等の特別な装飾は付けない（自己説明的な名前＋正しい位置だけで十分なため）。あわせて、`その他（自由記入）`のまま現在の評価時期で全員未評価（レベル0）の行は、マトリクス・モバイル一覧（`isEmptyOtherPlaceholder()`）でのみ非表示にする（誰も使っていないプレースホルダー行の空欄クラッター対策。レーダーチャートの軸としては引き続き表示する。チームで比較する軸の本数がメンバーによって変わってしまうと集計が壊れるため）
- **参考メンバーのピンク表示**（2026-08-18追加、同日中に判定方法を変更）：部長・百瀬陽一が自分のスキル・資格を参考値として登録したケースを、マトリクス・保有資格表の列見出し（ピンク背景＋🍑アイコン、`isRefMember()`/`memberThHTML()`）と列全体（薄いピンクの縦帯＋左境界線、`memberTdOpen()`）、レーダーチャート／モバイル一覧のメンバーチップ（`.ref-chip`、🍑アイコン付き）、「重ねて比較」セレクトの選択肢で見分けられるようにする。「ライン外・参考値」等の説明文言は付けない（アイコン＋色だけで十分という判断）。ピンクの色トークン（`--pink`/`--pink-dim`）はstyle.cssに追加済み
  - **対象は`teamRosterMembers`との不一致による自動判定ではなく、`REFERENCE_MEMBERS`（明示的な氏名リスト、現状`['百瀬 陽一']`）で管理する**。当初は在籍名簿に無い人を自動でピンクにする実装にしていたが、「新たに配属される社員」が名簿（member_master.csv）登録前の一時的な期間だけmembers末尾に混ざるケース（表記ゆれ救済フォールバックと同じ仕組み）まで誤って参考データ扱いになってしまうため、明示リスト方式に変更した。今後また参考値のみのメンバーが出た場合は、その都度`config/org.json`の`referenceMembers`に氏名を追記する運用（自動追随はしない。2026-09-11以降、実体はmember.html・skill.html双方とも`config/org.json`から読み込む）
- スキル検索の棒グラフの色は「レベル」（1〜5）の値そのものから決まる固定の意味づけ（4以上=green／3=blue／2=amber／1=red）
- 「備考」列はマトリクスのドットのホバー（title属性）に加えて、ドットの下に小さいテキストとして常時表示する。ホバーのみだと見落とされやすいため。スキル検索結果でもバーの下に表示
- マトリクス（スキル・保有資格どちらも共通の`.matrix-tbl`）は`table-layout:fixed`＋メンバー列を均等固定幅にしている（2026-08-12修正）。以前はブラウザの自動列幅計算に任せていたため、備考欄に長文を書いているメンバーがいると、その列だけ異様に広がり列がガタガタになる不具合があった
- レーダーチャートは全スキル（現状49種）を一度に表示すると軸が密集して読めなくなるため、「分野」タブ（サブカテゴリ単位。サブカテゴリが無いスキルはカテゴリ単位でグルーピング）で絞り込んで表示する。分野の選択はメンバー切り替え・評価時期切り替えをまたいで保持される
  - **軸ラベルのフォントサイズはモバイル幅・軸数に応じて動的に縮小する**（2026-08-18追加）：「その他（自由記入）」の書き換え項目は同じ分野の軸としてまとまるため、書き換えが増えるほどその分野（現状はプログラミング言語）の軸数が増え続ける設計になっている。軸数9超（`labels.length > 9`）または画面幅480px未満のどちらかに該当すると9.5px、両方該当すると8pxに縮小する（`showRadar()`内の`crowded`/`narrowScreen`判定）。対応前は狭い画面で13軸表示時にラベルが重なって読めなかった
- **前回評価時期との比較表示**（2026-08-18追加）：選択中の評価時期がPERIODS配列上で2番目以降、かつ本人がその1つ前の時期に既にヒアリング済み（`memberPeriodHasData`で判定。その時期に1件でもレベル入力がある＝実施済みとみなす）の場合、レーダーに前回分の値をグレーの点線で重ねて表示し、上部の注記に前回比の合計差分（例：「合計 前回比 +1.5」）を出す。総合タブ（分野平均）・個別分野タブどちらでも同じ仕組みで動く。初回の評価時期（2026年8月のみ入力済みの現時点）は比較対象が無いため点線は出ない。次回（2026年11月）のヒアリングデータが入り次第、自動で機能し始める設計
- **「チーム全体」レーダー**（2026-08-18追加）：メンバーチップの先頭に擬似メンバー`👥 チーム全体（○名平均）`（内部キー`TEAM_KEY`）を追加。選択すると、表示中の軸（総合タブ＝分野平均、個別分野タブ＝スキルレベル）ごとに全メンバーの平均・最小・最大を算出し、①最小〜最大の帯（塗りつぶし。Chart.jsの2データセット＋`fill:'-1'`で表現）②チーム平均の実線③（任意）比較メンバーの点線、を重ねて表示する。前回評価時期との比較（上記）はチーム表示では対象外（個人選択時のみ）。この擬似メンバーはレーダーチャートタブ専用で、マトリクスタブのモバイル一覧（`mobileMatrixChips`）には出さない（チーム集計の一覧表示は未実装のため）。`selectMember()`・`buildMemberChips()`はこの擬似メンバーかどうかで分岐しており、チーム選択時はモバイルのスキル/資格一覧・マトリクス側の選択状態には影響しない
  - **比較線（③）のモード切り替え**（2026-08-18追加）：チーム全体選択時のみ表示される「重ねて比較」セレクト（`teamCompareMode`、既定`__auto__`）で3通りから選べる。`__auto__`＝`localStorage`の`you_widget_member`（you-widget.jsが使うキーをそのまま流用）と連動し、「あなたの状況」で選ぶ人が変わるたびに自動で追従。`__none__`＝重ねない。それ以外＝メンバー名を直接指定し、「あなたの状況」の選択とは無関係に固定表示（you-widget側で誰が選ばれていても変わらない）。自動追従は`you-widget.js`が選択変更のたびに発火する`you-widget-changed`カスタムイベント（`window.dispatchEvent`）をskill.html側で購読し、チーム表示中かつ`__auto__`の時だけ`showRadar(TEAM_KEY)`を再実行する仕組み。**注意：** `you-widget.js`側はこのイベントを`localStorage.setItem`の**後**に発火させること（先に発火させると、購読側が読みに行った時点でまだ書き込み前の古い値を拾ってしまう不具合を2026-08-18に一度踏んでいる）
  - **平均・最小〜最大の集計対象は`teamRosterMembers`（在籍名簿と一致した人のみ）に限定**（2026-08-18追加）。`members`配列には、名簿に一切見当たらない名前（表記ゆれ救済のほか、部長など名簿対象外の人のスキル・資格を試しにNotionへ入力した場合も含む）が末尾に混ざることがあり、これをそのままチーム平均に含めると集計が歪む。マトリクス・保有資格表・比較線（③、`teamCompareMode`で個別に指定した場合）では引き続き`members`をそのまま使うため、名簿対象外の人の列やデータは今まで通り見える（無言で消えるとNotion入力ミスに気付けないため）が、「チーム全体」の平均・最小〜最大・「◯名平均」の人数表示だけは名簿対象外の人を含まない
- マトリクスタブ内に「💯 保有資格」カードを追加。`data/certifications.csv`が存在すれば資格名×メンバーのマトリクスを表示（無い/空でもスキルマップ本体の表示は壊れない）。詳細はdata/certifications.csvのデータフォーマット節を参照
- 分野タブの先頭に「総合」を用意し、デフォルト表示はこれ。各分野（サブカテゴリ）に属するスキルレベルの単純平均を軸にした俯瞰表示で、個別スキルの内訳は各分野タブから確認する。平均値は未評価スキル（レベル0）も含めて算出するため、未評価が多い分野は低く出る点に注意
- マトリクスタブは画面幅700px以下で表示を切り替える（`.desktop-only`/`.mobile-only`クラス＋メディアクエリ）。デスクトップは通常の横長マトリクス、モバイルは「メンバーを選択」チップ＋選んだ1人のスキル一覧（分野ごとにグルーピング）／保有資格一覧を縦一覧で表示する。メンバー×スキル・メンバー×資格を10列前後横に並べると狭い画面では窮屈になるための対応。このモバイル用チップとレーダータブのメンバーチップは`selectMember()`で連動しており、どちらで選んでもレーダー・モバイルのスキル一覧・資格一覧が同時に切り替わる。セルの中身（レベルドット・資格の保有状態）は`skillDotHTML()`/`certCellHTML()`としてデスクトップ表とモバイル一覧の両方から共通で呼び出している
- **「あなたの状況」ウィジェット（you-widget.js。全ページ共通）からの遷移をURLパラメータで受け取る**（2026-08-09追加、2026-08-11にウィジェット自体が全ページ共通化）：`?member=氏名`で該当メンバーを初期選択（`renderMemberChips()`に渡す。名簿に無い/未指定なら従来通り先頭の人）、`&tab=radar`でレーダーチャートタブを自動で開く、`&group=分野名`でレーダーの分野タブを自動選択（`groups`配列に一致する`key`が無ければ無視し既定の「総合」のまま）、`#certifications`（保有資格カードの`id`）でそのカードまで自動スクロールする。組み合わせ自由（得意なスキル分野からは`?member=...&tab=radar&group=...`、保有資格からは`?member=...#certifications`で遷移してくる）
