# member.html（メンバー）

> ルート`CLAUDE.md`から分離した開発メモ（2026-11-08）。該当ファイルを変更する前に読み、構造に関わる変更をしたらここを更新すること。
> 文中の「〇〇.htmlセクション」は`docs/dev/pages/〇〇.md`、「△△.js節」は`docs/dev/shared/`、「データフォーマット節」は`data/CLAUDE.md`、「組織設定」節・「技術スタック」節はルート`CLAUDE.md`を指す。

- ステータスが「在籍」の行のみ表示、CSV行順固定
- タブ5種：ALL / ライン別 / 役職別 / 等級別 / 委員会別
- 顔写真：`data/members/氏名.png`（Notionの氏名と完全一致）
- 社歴：入社年月日からJavaScriptで自動計算（calcTenure）
- 在籍者一覧では備考・社歴・画像列はCSVから読まない

ライン別タブのLINE_META（管理者名）：
```javascript
'第1ライン':   { manager: '米花 雅史' }
'第1-1ライン': { manager: '伊藤 良多' }
```

**注意：** `member_master.csv`の「所属ライン」列はNotion側で「誰の配下か（上司名ベース）」の表記になっており、会社組織上の名称とは異なる（例：`百瀬 陽一Bライン`＝`第1ライン`、`米花雅史Ｋライン`＝`第1-1ライン`）。member.html内の`LINE_LABEL_MAP`でCSVの生値を組織上のライン名に変換してから表示・集計している。

LINE_COLORS・LINE_META・LINE_LABEL_MAP・REFERENCE_MEMBERSは、2026-09-11以降`config/org.json`から読み込む（member.html内では`let`宣言のみで、実体は`init()`冒頭の`applyOrgConfig()`が設定する。詳細は「組織設定（config/org.json）」節を参照）。ラインが変わった場合、または所属ラインの生値の表記が変わった場合は`config/org.json`を更新すればよく、member.html本体には手を入れる必要がない。

- メンバー一覧の下に、`data/org_chart.csv`から組織構成図ファイルへのリンクをチップ形式で表示する。**ALLタブのときのみ**表示し、それ以外のタブ（ライン別・役職別・等級別・委員会別）では非表示（switchTab内でorgChartSectionの表示・非表示を切り替え）。ファイルは最大でも年12件（2026/8〜2027/7の月次更新）想定のため、アーカイブ等の絞り込みはせず全件表示。CSVが空、または取得に失敗してもメンバー一覧本体の表示は継続する（catchで握りつぶす）
- **「異動・退職者」セクション**（2026-08-12追加、2026-09-01にステータス別へ分割）：組織構成図チップのさらに下に、ステータスが「在籍」以外の行を表示する。ステータス値（`異動`／`退職`）ごとに**別々の折りたたみ（`<details>`、既定で閉じた状態）**に分け、「異動者」「退職者」を混在させない（`FORMER_GROUPS`定数。開閉挙動はinfo.htmlのアーカイブ切替と同じ考え方）。想定外のステータス値が来た場合は「その他」グループとして取りこぼさず表示する（フォールバック）。表示は**氏名＋Notion「備考」列の一言コメントのみ**（例：「10月より第2ラインへ異動」）で、日付・異動先を別項目に分解しない。備考が空の行は「—」を表示。組織構成図チップと同様に**ALLタブのときのみ**表示する（`renderFormerSection`/`updateFormerSection`、switchTab内で開閉と連動）。該当行が1件も無ければグループごとセクション自体を出さない。この一覧はあくまで「今誰がいないか」を軽く示すだけの位置づけで、異動という出来事の正式な記録はchronicle.html（ライン年表）側に手動で残す運用（member.html側からの自動連携はしない）
