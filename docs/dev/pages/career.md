# career.html（キャリアロードマップ）

> ルート`CLAUDE.md`から分離した開発メモ（2026-11-08）。該当ファイルを変更する前に読み、構造に関わる変更をしたらここを更新すること。
> 文中の「〇〇.htmlセクション」は`docs/dev/pages/〇〇.md`、「△△.js節」は`docs/dev/shared/`、「データフォーマット節」は`data/CLAUDE.md`、「組織設定」節・「技術スタック」節はルート`CLAUDE.md`を指す。

- 部下が「自分は次に何をすればいいか」を確認するためのキャリアナビ。データ源はNotion/CSVではなく、SYSホールディングスグループ「職務要件・昇格基準定義書」（更新日：2025年4月24日）の**3SEシステム部・情報戦略グループ列**を抜粋し、`career.html`内のJSオブジェクト（`COMMON_GRADES`／`FORK_GRADES`）に直接ハードコーディングしている（営業職・事務職等、他グループの基準はこのページには含まれない）
- 会社の昇格基準は1〜4等級が共通キャリアパス、5等級以降で「🧑‍💼リーダー・管理職コース」と「🧑‍💻スペシャリストコース」の2コースに分岐する構造（会社の公式な組織区分をそのまま踏襲）
- 上部にインタラクティブなロードマップ（等級ボックスをクリックすると選択状態になる）、その下に「現在地・次のステップ」詳細パネルを表示。4等級選択時のみ、5等級で分岐する両コースを並べて提示する特別レイアウトになっている（`renderDetail()`内で`selectedGrade === 4`を判定）。5等級以降を選択した場合は選んだコード（`selectedTrack`）を維持したまま次の等級のみ更新する
- 各等級の「昇格基準（公式基準）」は`req`配列で保持し、文字列（単純な箇条書き）・`{text,note}`（資格未取得時の給与減額など注記付き）・`{either:[...]}`（「以下のいずれかを満たすこと」の代替要件グループ）の3種類の要素を混在させられる（`reqItemHTML()`が判定して描画）。**「経営会議メンバー」要件は8〜10等級のリーダー・管理職コースのみに付き、スペシャリストコースには付かない**（原本のPDFで実際にそう記載されているため、コピー時に混同しないよう注意）
- 各等級の「成長のための経験例」（`EXP_COMMON`／`EXP_FORK`）は会社の公式昇格基準ではなく、**第1ラインが独自に整理した参考情報**。ページ内でもその旨を明記している。会社側の基準定義書が改訂された場合はこの経験例も含めて内容の見直しが必要
- 定義書の改訂（等級・職位名・要件の変更）があった場合は、`career.html`内のデータをその都度手動で更新すること（自動同期の対象外）
