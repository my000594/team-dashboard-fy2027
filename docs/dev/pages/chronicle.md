# chronicle.html（ライン年表）

> ルート`CLAUDE.md`から分離した開発メモ（2026-11-08）。該当ファイルを変更する前に読み、構造に関わる変更をしたらここを更新すること。
> 文中の「〇〇.htmlセクション」は`docs/dev/pages/〇〇.md`、「△△.js節」は`docs/dev/shared/`、「データフォーマット節」は`data/CLAUDE.md`、「組織設定」節・「技術スタック」節はルート`CLAUDE.md`を指す。

- `data/chronicle.csv`をfetchし、入社・異動・退職・ライン別MVP・資格取得・イベントを月別グルーピングの縦タイムラインで表示する。第1ラインの一年を振り返るための機能で、career.htmlとは異なりNotion API自動同期のCSVを使う（手動バッチ運用のupdate_*.batは無し）
- 期（FY）はAugust始まり・7月終わりで判定（`fyOf()`：月が8以上ならその年+1、7以下ならその年がFY）。FYセレクタは実データに存在する期＋今日が属する期を常に候補として出し、今日が属する期にデータがあればそれを既定選択、無ければデータのある最新の期を選ぶ
- 種別（入社／異動／退職／ライン別MVP／資格取得／イベント）ごとに色（green/amber/red/purple/cyan/blue）とアイコン絵文字を`TYPE_META`で固定的に割り当てている（knowledge.html・skill.htmlのカテゴリ色のような動的割り当てではない。種別の選択肢自体を増やす場合はこの定数の更新が必要。2026-09-29にNotion側の選択肢を`参画`→`入社`・`ライン内MVP`→`ライン別MVP`にリネーム、`退職`を新規追加した際、`TYPE_META`/`TYPE_ORDER`が追随できておらず退職イベントがタブ・ダイジェストに出ない不具合があったため修正した）
- 上部にダイジェスト集計（選択中の期における種別ごとの件数）と種別フィルタタブを表示し、フィルタはクライアント側でその場に絞り込む。**選択中の期に1件も実績が無い種別は、ダイジェストカード・フィルタタブどちらにも出さない**（「異動 0」「ライン別MVP 0」のように0件の種別を表示すると、異動やMVPの有無について憶測を招きかねないための対応。「すべて」タブは0件でも常に表示する）
- 「氏名」はメンバーマスタへのリレーション（複数選択可）。ライン全体向けのイベント（懇親会・全体会議等）は空欄でよく、その場合はアバターの代わりに種別アイコンを表示する。複数名の場合はカンマ区切りで氏名を連結し、アバターは先頭の1名の頭文字を表示する
- 「ステータス」が「予定」の項目には「予定」バッジを表示し、確定前の将来予定（年間表彰の発表など）も年表に置ける設計にしている
- **添付ファイル**（2026-08-20追加）：表彰状の画像・PDF等をイベントに紐づけて表示できる。Notion側「添付ファイル」プロパティ（files型）から抽出し、meeting_plan.csvの「資料リンク」と同じ「表示名|URL」形式（複数ある場合はカンマ区切り）でCSVに出力する。Notion直アップロードは期限付きURLになるため、meeting_plan.csv・org_chart.csv・certifications.csvのデジタルバッジと同じ理由で外部ドライブのリンクを登録する運用とする。表示名が未設定の場合は「添付ファイル」（複数件あるときは「添付1」「添付2」…）にフォールバックする。ライン別MVPの表彰状に限らず、入社・異動・退職・資格取得・イベントいずれの種別でも同じ仕組みで添付できる（種別による出し分けはしていない）。各イベントカードの本文（詳細）の下に📎アイコン付きのリンクチップとして表示し、クリックで新規タブで開く。添付が無いイベントはチップ自体を表示しない
- 日付列はinfo.csvと同じく`YYYY-MM-DD`のISO形式のままCSVに出力している（sales.csv・meeting_plan.csvのように日本語表記に変換していない）。`new Date()`でそのままパースできるため、sales.htmlで踏んだ「日本語日付文字列だとInvalid Dateになる」問題を最初から回避している
